## 概述

2026年7月，OpenAtom openEuler（简称“openEuler”或“开源欧拉”）社区持续推进技术演进与生态建设协同发展，社区规模与活跃度稳步提升，用户、开发者及单位成员数量持续增长，社区贡献不断积累。截至7月底，社区用户累计超过824万，开发者超过2.8万名，单位成员达2176家，开源生态影响力持续扩大。 在生态建设方面，社区持续推进国际化生态拓展，参与开放原子“园区行”香港站活动并推动openEuler香港用户组成立，进一步强化区域开源生态连接；另外，亮相LEAP East 2026，积极参与全球开源技术交流，加速构建开放协同的国际化生态网络。在技术创新方面，社区围绕AI与操作系统融合持续探索，进一步增强Agentic AI场景适配能力；同时围绕AI原生软件工程、AI Agent交互平台、系统Agent及智能调优等方向持续布局，推动智能化基础设施能力演进。整体来看，openEuler社区持续强化开源生态连接能力与智能化技术创新能力，加速构建面向AI时代的新一代操作系统基础设施。

（本月报阅读时长约8分钟）

### ➣开放原子“园区行”走进香港，共筑开源欧拉国际化开源生态

7月29日，开放原子 “园区行” 香港站 —— 开源生态国际化暨开源欧拉 （openEuler）香港启航专场活动于香港顺利举办。本次活动由开放原子开源基金会主办，香港物流及供应链多元技术研发中心（LSCM）、openEuler社区承办。活动汇聚香港政企机构、高等院校多方力量，共同探讨内地与香港科创协同，助力香港打造联通内地、辐射全球的开源技术枢纽。

### ➣openEuler香港用户组正式成立

7月29日，在开放原子 “园区行” 香港站 —— 开源生态国际化暨开源欧拉 （openEuler）香港启航专场活动现场，正式宣布openEuler 香港用户组成立。近年来，openEuler社区发展迅猛，已成为中国数智基础设施的基石，并正式启动国际化进程。香港用户组的成立，标志着openEuler将以香港为枢纽，深度融入全球开源生态，吸引全球企业与开发者共建AI开源生态。

### ➣openEuler社区正式发布《生成式AI工具使用与开源贡献策略》

openEuler社区秉持开放、协同、创新的开源精神，将生成式AI与智能化Agent视为推动社区技术演进的重要生产力。社区允许贡献者在合理、透明、可审查的前提下使用生成式人工智能工具辅助贡献，但坚持“保持开放，AI开发导向”，“开发者最终负责”，“透明度，可追溯”三大核心原则。

本策略适用于贡献者向openEuler社区（包括但不限于openEuler组织下的所有代码仓库、文档库等）提交的各种形式的所有贡献：

源代码与脚本：包括各类核心代码、测试用例、构建脚本。技术文档与社区内容：包括API说明、部署指南、发布日志、Wiki页面等。配置与元数据：包括Containerfile/Dockerfile、CI/CD配置文件等。

## 技术进展

### ➣openYuanrong v0.9.0版本正式发布

7月8日，openYuanrong 团队正式发布 openYuanrong v0.9.0，重点强化Agentic AI场景适配能力，多场景核心性能与实用性大幅优化。版本针对三大核心场景完成迭代升级：Agent场景新增企业级Agent分布式运行时，赋能Agent规模化生产落地与高效运维，具备会话上下文亲和、多租户隔离、自动弹性扩容等企业级能力；AgenticRL场景优化沙箱使用体验，支持沙箱动态路由注册与反向隧道能力，打通异构集群双向网络通信壁垒；推理场景聚焦性能与可靠性提升，依托NUMA感知、链路预热优化分布式数据访问效率，升级KV Cache数据传输性能，同时支持数据异步持久化存储，强化数据可靠性与问题排查定界能力。

### ➣openEuler intelligence SIG 提出 AI 原生软件工程范式并构建开源项目AET

2026 年，AI 已从“编码助手”进化为工程执行主体。但有个反直觉的事实越来越难忽视：AI 帮我们拔高了能力上限，却在规模、效率、质量三个维度上制造了新的挑战。 为此，openEuler intelligence SIG 提出 AI 原生软件工程（AI-Native Software Engineering）范式，并构建了开源项目 AET（Agentic Engineering Team），旨在推动企业级 AI 编码方案落地，实现可靠、可控、可演进的软件交付。

![alt text](10.png)

原文阅读：[openEuler Agent Infra企业级编码方案：基于AI原生软件工程范式，实现企业级软件交付可靠、可控、可演进](https://mp.weixin.qq.com/s/tjHbA0V3UnxRSv7XlVgdKQ)

### ➣openEuler 社区孵化自托管 AI Agent 交互平台——PolyMind

在 AI Agent 技术快速发展的背景下，如何高效地管理、编排和运行多个智能体，并为其提供丰富的工具与技能生态，成为当前 AI 基础设施领域的关键挑战。

面向这一需求， openEuler的创新版本DevStation，提供了一个原生集成 agentd 服务的自托管 AI Agent 交互平台——PolyMind。该平台由 openEuler 社区孵化，致力于将 AI 对话、Agent 工作流编排与多模型管理融为一体，提供开箱即用的完整解决方案。目前，PolyMind 已在 Agent 运行时生命周期管理、技能生态建设、模型统一管理、安全漏洞自动化修复等方面取得了显著进展。

![alt text](11.png)


原文阅读：[DevStation智能助手：AI Agent 交互平台的新范式](https://mp.weixin.qq.com/s/exZ0n3CXXb3EclZ6UUcTew)

### ➣openEuler Agent Infra 智能调优引擎：自上而下深入识别 OS 层性能瓶颈，根因定位自主下钻，调优分析效率提升 50%+

在现代数据中心和云原生场景下，操作系统层性能调优是保障业务服务质量的关键环节。然而，随着硬件架构日趋复杂（多路NUMA、异构计算、高速存储网络），特别是超节点异构融合需求背景下，节点组件层数倍增，OS层性能瓶颈的根因定位难度正呈指数级增长。面对复杂场景下的挑战，openEuler 社区推出 Agent 时代的 OS 层智能调优引擎。

### ➣AcTrail：为 Agent 应用打造系统侧观测与治理底座

随着 AI Agent 从回答工具走向生产执行主体，企业不能只依赖应用层日志或框架自报来判断其行为，而需要看清模型决策、工具调用、系统资源访问和治理处置之间的完整链路。AcTrail 通过系统侧观测与跨层行为关联能力，将进程、文件、网络、模型交互和敏感访问处置统一到可追溯的行为轨迹中，为Agent应用提供真实行为观测、行为数据可审计分析、运行过程可治理控制的能力底座。

![alt text](13.png)

原文阅读：[AcTrail：为 Agent 应用打造系统侧观测与治理底座](https://mp.weixin.qq.com/s/9fn-7jhWmx-XEgzwpFvljQ)

### ➣服务器 OS 的系统 Agent：面向系统的自治与管理中枢

随着 AI 能力提升，AI Agent 正从单轮对话工具，进化为能执行命令、修改文件、管理进程的系统核心角色。这种能力的飞跃，让 Agent 展现出高效执行力的同时，也带来了严峻的管控挑战。为了应对该挑战，openEuler 社区提出“系统 Agent”这一新定位——其职责不仅是让单台/一组服务器具备自感知、自诊断、自优化、自修复的能力；同时向上服务于各类 Agent 应用，负责 Agent 的调度和切换；向下负责统一虚拟化、内存、网络等系统资源。旨在激活 Agent 和系统的结合能力，从而实现 AI 对真实的系统资源、系统问题的自治和优化，并进一步管理、优化在服务器 OS 上的其他海量 Agent 应用。

![alt text](14.png)

原文阅读：[openEuler Agent Infra 系列 | 服务器 OS 的系统 Agent：面向系统的自治与管理中枢](https://mp.weixin.qq.com/s/k4ubkPR-H8g852CggFJfgg)

### ➣Witty CLI： 让 openEuler 系统更智能、更高效

Witty 的整体架构自上而下贯穿用户接入、运维智能体、运维底座、智能平台、基础设施五个层次，同时覆盖通算（传统集群/单机）和智算（超节点）两种算力形态。在这套体系中，Witty CLI 是用户最直接接触的智能交互入口。它把终端变成对话窗口：用户用自然语言描述运维意图，Witty CLI 负责调度底层运维智能体、模型与知识库完成任务，覆盖通算与智算超节点两种算力形态。
